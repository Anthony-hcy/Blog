# 博客使用指南（新手版）

你的博客已部署在 GitHub Pages。下面是日常使用方法。

## 一、我的博客在哪

- 线上地址：**https://anthony-hcy.github.io/Blog/**
- 仓库地址：https://github.com/Anthony-hcy/Blog
- 每次推送到仓库的 `main` 分支，GitHub Actions 会自动重新构建并发布，等 1~2 分钟即可看到更新。

## 二、怎么发第一篇文章（两种方式）

### 方式 A：网页后台（Blog Portal，推荐，手机上也能用）

1. 打开 `https://anthony-hcy.github.io/Blog/portal.html`
2. 登录需要：
   - **Owner/Repo**：`Anthony-hcy/Blog`
   - **Personal Access Token**：需要你自己创建一个 GitHub Token
     - 打开 https://github.com/settings/tokens → Generate new token (classic)
     - 勾选 `repo` 权限（写仓库内容必须）
     - 生成后复制那串 `ghp_...` 粘贴进来（Token 只存在你自己浏览器里，安全）
3. 点 **Posts → New post** 写文章，点 **Save & Publish** 即提交，自动触发重建。

### 方式 B：直接在仓库里写（电脑上）

在仓库 `content/posts/` 目录新建 `.md` 文件：

```markdown
---
title: 我的第一篇文章
date: 2026-09-04 10:00:00+08:00
slug: my-first-post
type: post            # post=长文, memo=短篇（朋友圈式）
category: 日常
tags: [生活, 记录]
excerpt: 可选，列表页显示的摘要
banner: /assets/img/post/cover.png   # 可选封面图
draft: false          # true 则不发布
---

正文 Markdown…
```

保存后 push 到 main 分支即可。

## 三、怎么改站名、头像、简介

打开仓库根目录的 `site.config.json`：

```json
{
  "site": {
    "name": "你的站名",
    "subtitle": "一句话简介",
    "author": "你的名字",
    "url": "https://anthony-hcy.github.io/Blog",
    "base": "/Blog",
    "social": { "github": "https://github.com/你的名字", "weibo": "", "twitter": "" }
  }
}
```

- 站名：改 `name`
- 头像/Logo：替换仓库里 `site-root/logo.png`（180×180）
- 侧边栏社交链接：填 `social` 字段

## 四、怎么传图片

1. Portal 后台 **Images** 页签：填文章 slug → 选图片 → Upload
2. 图片会上传到 `static/assets/img/<slug>/`，得到引用：
   ```
   ![](/Blog/assets/img/<slug>/图片名.png)
   ```
3. 写文章时把这段引用粘贴进正文即可，图片会自动支持点击放大。

> **两个硬约定（不满足时构建会报错）**
> - `slug` 必须与图片文件夹 `static/assets/img/<slug>/` 的名字**逐字一致**（`2026-10-01` 与 `2026.10.01` 这类横线/点号差异也算不一致）。不一致时构建会中止，不再像以前那样把 `![[...]]` 原样输出到页面。
> - 同一行里连着写多张图（`![[图1.png]]![[图2.png]]![[图3.png]]`）会自动并排：电脑端一行最多 3 张，手机端自动退化为一张一行；中间插一个空行就会另起一行。与 Obsidian 里的行为一致。
>
> 另外：改 `slug` 后旧地址会失效，构建脚本里的 `REDIRECTS` 表可以为旧地址生成自动跳转页。

### 4.1 实况照片（Live Photo / 动态照片）

上传时每张图会先进入「确认上传」预览页，右下角带一个**实况**勾选框：

- **一加/OPPO 手机拍的动态照片**：直接选中上传即可。系统会自动识别（检测内嵌视频 + OPPO 标记）、自动拆成「封面图 + 视频」一对、自动勾选实况——你只需点「确认上传」。
- **手动传两个文件**：选一张图 + 一个同名视频（如 `IMG_1.jpg` 和 `IMG_1.mp4`）一起上传，图片勾上实况即可配对。
- **普通图片**：不勾实况，行为与以前完全一样。
- 预览页里如果出现黄色「HEVC」提示，说明视频是 H.265 编码。**仓库只提交 H.264 兼容版（`.avc.mp4`）**，所以手机和电脑浏览器（Chrome/Firefox/Edge/Safari）都能播放。

**推荐流程（控制仓库体积）**：上传实况图后，在电脑上处理一次再提交：

```bash
node scripts/media-prep.mjs --backup D:\Blog-backup   # 转码 avc + 生成缩略图，原片备份到 D:\Blog-backup
```

然后 `git add` 时只提交 `.avc.mp4` 与 `.jpg/.thumb.jpg`，把 HEVC 原片从仓库删除（原片在备份目录里）。CI 里保留了 ffmpeg 兜底：如果忘了处理直接 push，CI 会自动转码并生成缩略图，站点不会坏，只是仓库会多一份原片体积。

> **CI 什么时候才装 ffmpeg**（`.github/workflows/deploy.yml` 的 `Check ffmpeg needed`）：只认两类“真缺件”，都在 `static/assets/img/gallery/` 里查——①有原片 `.mp4` 但没有同名 `.avc.mp4`；②有图片但没有同名 `.thumb.jpg`。两个条件都不成立就**跳过安装**，普通改文章/说说约 25 秒跑完。判定口径与 `scripts/build.mjs` 里 `tryTranscodeLiveVideos()` / `tryMakeThumbnails()` 完全一致，两边任意一边改了都要同步。
>
> 真缺件时也别慌：静态包会走 `actions/cache` 缓存（key `ffmpeg-static-amd64-v1`），第一次下载后，之后命中缓存解压只要 1~2 秒；下载源按 GitHub Releases（BtbN）→ johnvansickle → apt 的顺序兜底。
>
> **Portal 传图会自动带缩略图**：在 Portal 上传图片（说说和文章都算），浏览器里会用 canvas 生成 480px 的 `.thumb.jpg` 一起提交，所以日常发图不会再触发上面第②条。只有从 GitHub 网页直接拖图进 `gallery/`、或上传实况视频（原片 `.mp4` 没转码）时才会触发。

发布后查看效果：

- **手机 / 电脑**：点开图片（进入大图）后，**左下角出现 ▶ 按钮**，点击播放。
- 实况**播一遍自动停止**、自带声音；播放中点 ▶ 可提前停止，再点重新播放。
- 页面缩略图右下角有 LIVE 角标，点击缩略图即可进入大图播放。

> 注意：动态照片原文件一般 8MB 以上（视频藏在图片文件里）。聊天工具转发时若被压缩成几百 KB 的静态图，动态就丢了，请用「原图/原文件」导出。

## 十、关于页的「编年史」时间线

关于页 `https://anthony-hcy.github.io/Blog/about/` 最下面是一条竖线时间线，数据单独放在 `content/chronicle.json`（不写在 `about.md` 里，避免和文章正文混在一起）：

```json
{
  "title": "Chronicle",
  "intro": "一句话说明，可留空",
  "entries": [
    { "date": "2026-09-04", "tag": "建立", "title": "事件标题", "desc": "具体说明。" },
    { "date": "",           "tag": "日常", "title": "只记得大致阶段的条目", "desc": "date 留空时左侧不显示时间。" }
  ]
}
```

- `date` **可留空**：留空则该条只显示标题和说明，不占时间；格式随意（`2026-09-04` 或 `2026-09-04 15:18` 都行，脚本按原样输出）。
- `tag` 可选，渲染成标题后面的小胶囊；填 `修复` 时自动用橙色（与站点强调色一致）。
- `order` 默认 `"desc"`（**最新在上**）：数据文件里按时间正序追加新条目即可，渲染时自动倒序；想改成旧在上就把 `order` 写成 `"asc"`。显示顺序只由这个字段决定，脚本不会按 `date` 自动排序。
- 增删条目后跑一次构建（`node scripts/build.mjs`，或直接推送让 GitHub Actions 构建）即可生效。
- 样式（竖线、圆点、窄屏折行）在 `build.mjs` 的 `CHRONICLE_CSS` 常量里，改配色时用站点的 CSS 变量（`--accent` / `--rule` / `--text-3`）。

> 本地预览注意：站点 base 是 `/Blog`，直接 `python -m http.server --directory dist` 打开 `http://127.0.0.1:8080/about/` 时 `/Blog/assets/main.css` 会 404，页面会丢失主题样式（表现为时间线只剩文字、竖线和圆点不见了）。预览时要么把 `dist` 挂在 `/Blog/` 路径下，要么访问线上页面。**更省事的解法见下一节：构建根路径版来预览。**

> **Vercel 海外托管（免备案）**，`haelcy.cn` 与 `www.haelcy.cn` 均已上线；阿里云服务器已退款、
> `deploy/` 下的 nginx / 服务器脚本全部废弃。Cloudflare Pages 项目与 `pre.haelcy.cn` /

站点现在有四个入口，**同一份源码、同一个 commit**（只是前缀不同）：

| 入口 | 角色 | 内容形态 | 由谁构建 |
|---|---|---|---|
| `https://haelcy.cn/` | **主站**（canonical 指向它） | 根路径（无 `/Blog`） | **Vercel**（Git 集成，push 即部署） |
| `https://www.haelcy.cn/` | 主站别名，**只跳转、不建站** | 无独立产物 | Vercel 边缘 **308 → `https://haelcy.cn/`**（路径保留） |
| `https://haelcy-blog.vercel.app/` | Vercel 项目默认别名（回退入口） | 同主站 | Vercel |
| `https://anthony-hcy.github.io/Blog/` | GitHub Pages 镜像（保留） | `/Blog` 前缀 | GitHub Actions |

> `*.vercel.app` 在国内**被按 SNI 阻断**（同一个 IP 把 SNI 换成自有域名就正常），且域名解析被污染，
> 所以对外一律用 `haelcy.cn`；`www` 则保证别人直接敲 www 时不会 404。

构建命令（同一份源码靠环境变量切形态）：

| | GitHub Pages | 自有域名（主站） |
|---|---|---|
| 构建命令 | `node scripts/build.mjs` | `SITE_URL=https://haelcy.cn SITE_BASE=__root__ node scripts/build.mjs` |
| URL 前缀 | `/Blog` | `/`（根路径） |
| 托管 | GitHub Pages | Vercel |
| 更新方式 | Actions 自动部署 | 同一个 push 触发 Vercel 自动部署 |

### 关键：`site.config.json` 不用改

Pages 是**项目站**，必须带 `/Blog` 前缀；自有域名是**根路径**，两者冲突。
所以改成用**环境变量覆盖**（`scripts/build.mjs` 顶部处理）：

- `SITE_URL` → 覆盖 `site.url`（决定 canonical / sitemap / og:url 里的域名）
- `SITE_BASE` → 覆盖 `site.base`；**`__root__` 是约定值，代表空字符串**（根路径）

> 为什么用 `__root__` 而不是空串？「环境变量存在但为空」在不同 shell 下行为不一致，用约定值更可靠。

### 本地预览的正确姿势

```bash
# 根路径版：直接 http://127.0.0.1:8080/ 打开，样式和图片都正常
SITE_URL=http://127.0.0.1:8080 SITE_BASE=__root__ node scripts/build.mjs

```

（这也是上一节那个 `/Blog/assets` 本地 404 问题的解法。）

### 三处「只在根路径才暴露」的坑（已修，别改回去）

| 位置 | 原来怎么写的 | 为什么坏 | 现在怎么写的 |
|---|---|---|---|
| `layout.js` / `fcircle.js` / `portal-view.js` | 用 `location.pathname` 第一段猜站点根 | 根路径下猜不到 → `/fcircle/` 页会去取 `/fcircle/fcircle-data.json` → 404 → **朋友圈整页空白**；SW 注册和版本探测也 404 | 新增 `siteBaseFromScript()`：**按脚本自身 `src` 反推站点根**，两种部署都对 |
| `build.mjs` 渲染正文图片 | 原样使用正文里的 `href` | 历史文章里有 43 处 `/Blog/assets/...`（当初用 Pages 版 Portal 发帖写进去的），根路径下**图片全 404** | 统一走 `stripBase()` 剥掉历史 `/Blog/` 前缀 |
| `build.mjs` 跳转页 canonical | 直接拼 `site.url + target` | `/Blog` 部署下会拼成 `…/Blog/Blog/archives/…` | 改用 `SITE_URL + stripBase(target)` |
| `site-root/site.webmanifest` | 硬编码 4 处 `/Blog/` | 根路径下 PWA 图标 404、`start_url` 指向不存在的 `/Blog/` | 拷贝后按当前部署前缀统一改写 |

### 发布流程（三条内容来源，两个构建端）

| 内容从哪来 | 怎么进仓库 | 主站（Vercel） | 镜像（GitHub Pages） |
|---|---|---|---|
| 电脑写作 | `git push origin main` | Git 集成自动构建（1–3 分钟） | Actions 自动构建 |
| 手机发文章 / 说说 | `portal.html` 用你自己的 GitHub PAT 调 API 提交 | 同上 | 同上 |
| 每天 04:00 朋友圈采集 | `.github/workflows/fcircle-data.yml` 提交 `site-root/fcircle-data.json` | 同一提交自动重建 | 靠 `workflow_run` 监听该作业完成后再构建 |

- **为什么镜像那条要绕一层**：机器人用 `GITHUB_TOKEN` 提交**不会触发 `push` 事件**，所以
  `deploy.yml` 里加了 `workflow_run: ["Update Friend Circle Data"]` 兜底。
- **Vercel 不需要 Deploy Hook**：它走 Git 集成，机器人提交也会自动构建（实测提交后约 53 秒 Ready）。
- 主站不经过 GitHub Actions：Actions 里那次根路径版构建只是为了跑 `check-assets.mjs` 自检。
- **手机发文入口是 `https://haelcy.cn/portal.html`**（站点导航里的「手机发文」也指向它，产物里就是
  `href="/portal.html"`）。注意 Vercel **不做 clean URL**：手输 `/portal` 或 `/portal/` 都是 **404**。
  换 Vercel 之前是 Cloudflare Pages 托管，它默认把 `/portal.html` 308 成 `/portal`，所以旧记忆里
  `/portal` 能用。想恢复那种写法：在仓库根加 `vercel.json`（`{"cleanUrls": true}`，或把 `/portal`
  重定向到 `/portal.html`）——纯外观问题，不影响功能。

### 线上域名与 DNS（当前真实状态）

- **注册商**：阿里云（`haelcy.cn` 的 NS 就是在阿里云域名控制台改的）。
- **解析托管**：**阿里云云解析 DNS**（免费版），NS = `dns13.hichina.com` / `dns14.hichina.com`。
  2026-10-11 从 Cloudflare 迁过来，zone 里**只有三条记录**（TTL 10 分钟）：

| 类型 | 名称 | 目标 | 对外解析结果 |
|---|---|---|---|
| A | `@` | `216.198.79.1` | 直接返回 |
| A | `@` | `64.29.17.1` | 直接返回（与上一条轮询） |
| CNAME | `www` | `fea805c7d1d04106.vercel-dns-017.com` | CNAME 原样返回，跟随到 Vercel 任播 |

- apex 之所以用**两条 A 记录**：云解析不接根域 CNAME（Cloudflare 那边写的是 `CNAME @`，
  它自动扁平化成了同样这两个 IP）。
- `fea805c7d1d04106.vercel-dns-017.com` 是 **Vercel 面板给这个项目的推荐目标**（每个项目一个），
  在 Vercel 项目 → Settings → Domains 里能查到。
- **`www.haelcy.cn` 为什么能访问**：DNS 指向 Vercel → Vercel 认出 `Host: www.haelcy.cn` 是本项目的附加域 →
  自动签发 Let's Encrypt 证书（实测 `CN=www.haelcy.cn`，与 apex 是两张独立证书）→ 按面板里配的
  「Redirect to Another Domain / 308」在边缘直接返回 `Location: https://haelcy.cn/`。
  所以**站点里没有 www 版本**：HTML 里 `www` 出现 0 次，canonical 只有 `https://haelcy.cn/`。
- **DNS 提供商只决定「谁来回答 haelcy.cn 的 IP 是什么」，不参与网站本身**：内容始终由 Vercel 提供，
  换解析商不改变产物、也不改变速度（除非解析商自己解析慢）。之前慢是**橙云代理把流量绕到洛杉矶**，
  跟"DNS 托管在哪"无关。
- 迁移是**先补齐记录、再改 NS**（两边都指向 Vercel 同一组目标），所以切换期间零停机；
  具体步骤与复验命令见本节末尾「已完成：弃用 Cloudflare」。

### 缓存策略

构建给 JS/CSS/图片的 URL 都带内容哈希 `?v=`，所以：

- `/assets/*` → 可以长缓存（内容变则 URL 变，安全）
- `sw.js`、`version.json`、`fcircle-data.json`、HTML → **必须不缓存**（否则 PWA 会一直用旧 Service Worker）

Vercel / Cloudflare Pages 默认按文件类型给缓存策略，`sw.js` / `*.json` / HTML 默认即 `no-cache` 行为，**无需额外配置**
（原来那份 nginx 配置 `deploy/nginx-blog.conf` 已随服务器一起废弃）。

### 备案号（本项目已不需要）

海外托管**免备案** → `site.config.json` 里的 `icp` / `police` 两个字段**不用填**。

（这两个字段的能力保留着：万一以后搬回大陆服务器并完成备案，在 `site.config.json` 的 `site` 里加上

### 验收基线（本机广州、直连不走代理，可随时复验）

# DNS（本机唯一可用的公共解析是 AliDNS DoH；dns.google / cloudflare-dns 被墙）

curl -s "https://223.5.5.5/resolve?name=haelcy.cn&type=A"         # 期望：216.198.79.1 / 64.29.17.1

### 主站构建环境的一个注意（Vercel 上没有 ffmpeg）

- **实况照片**：Vercel 构建机**没有 ffmpeg**，不会在构建时转码，主站播放的就是仓库里提交的
  `.avc.mp4`。所以手机 Portal 发完实况图（它原样提交 `.mp4`）后，记得在有 ffmpeg 的电脑上跑一次

- **朋友圈数据**：`site-root/fcircle-data.json` 由 Actions 提交，不需要 ffmpeg，主站每次都会被自动重建。

## 十二、正文里的自定义写法：小字注释 `((…))`

从 Eyu.at 迁移过来的行内标记：用**双层圆括号**包住一句补充说明（旁白、吐槽、名词解释），渲染成灰色小字，并保留一层圆括号。

```markdown
补充一句 ((其实我也不太确定)) 就写到这里。
演出顺利结束了。((太好了))
AI((LLMs, 下同))发展得很快。
```

页面上会贴住前文显示：「补充一句(其实我也不太确定)就写到这里。」括号里那段字号 13px、颜色更淡（样式在 `static/assets/main.css` 的「行内小字注释」）。

规则（与 Eyu.at 一致）：

- 两个半角左括号 `((` 到两个半角右括号 `))` 必须写在同一行；内容里可以用全角括号 `（ ）`。
- 内容里**不能**再套半角括号 `( )`，否则不匹配，会原样显示成 `((…))`。
- 标记两侧的半角空格会被自动收掉，所以 `正文 ((注释)) 后文` 与 `正文((注释))后文` 渲染结果相同，都是紧贴的注释。
- 代码块、行内代码里的 `((…))` 原样显示，不会被替换。
- 列表页摘要里会还原成单层括号 `(…)`，并把两侧空格一起收掉。
- `post` 长文和 `memo` 说说用的是同一套渲染，两边都生效。

（早先那两篇示例文章 `test-inline-mark-post.md` / `test-inline-mark-memo.md` 已随测试清理删除；任意文章里写 `((…))` 都能用。）

## 十三、说说太长会自动折叠

首页 feed 里，memo 的**正文文字**超过 **150 字**时会自动折叠：只显示 6 行、底部渐隐，下面出现「展开」按钮，默认是折叠状态。

- 点「展开」看全文，按钮变成「收起」，再点回到折叠状态；按钮在正文右下角。
- 字数只算正文文字：**图片引用、链接地址、HTML 标签、Markdown 标记符、空白都不计入**，所以配几张图不会把短说说误折叠。
- 只有首页 feed 折叠；说说详情页 `/archives/<slug>/`、归档页、分类页、标签页都完整显示。
- 改阈值：`scripts/build.mjs` 里的 `const MEMO_FOLD_THRESHOLD = 150;`。
- 改折叠高度：`static/assets/main.css` 里 `.memo-fold.is-collapsed .memo-fold-clip` 的 `max-height: calc(1.8em * 6)`（6 = 行数）。
- 展开/收起逻辑：`static/assets/js/index.js` 的 `initMemoFolds()`（事件委托，无限滚动加载的旧分页 memo 同样有效）。
- 想复现：随手新建一篇 `type: memo` 的说说、正文超过 150 字即可看到折叠（计数规则见 `memoTextLength()`；早先的两篇测试说说已删除）。

## 十四、说说的头像会自动错开

首页每条说说左边有个小头像，来自 `static/assets/img/avatars/` 里的图片（现在 10 张），**不用手填**，构建时自动分配。

- **规则**：一条说说的头像不会和**前两条**说说相同（比如上上条用了 A、上一条用了 B，这次就只能从剩下 8 张里挑）。
- **为什么这么定**：完全随机容易连续撞车，看起来像卡图；按时间顺序分配能保证「同屏的几条一眼看出是不同的头像」。
- **历史不变**：分配是从**最早**的说说往后推的，所以**新发一条说说不会改动以前任何一条的头像**——已经发出去的样子不会变。
- **想手动指定**：在文章 frontmatter 里写 `avatar: /assets/img/avatars/avatar-3.webp`，这一条就固定用它；它的前后两条会自动避开这张。
- **放图**：把新头像丢进 `static/assets/img/avatars/`（jpg/png/webp/gif 都行）就进池子。张数变化会让整体重新洗牌一次，属于正常现象。
- 代码：`scripts/build.mjs` 的 `assignMemoAvatars()`（避重分配）、`memoAvatarHash()`（slug 哈希起点）、`MEMO_AVATAR_AVOID = 2`（避让条数，改成 1 就是只避开上一条）。
