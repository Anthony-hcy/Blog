# 项目结构

一句话：这是「源码 + 静态构建」型纯静态站。`node scripts/build.mjs` 读 `content/`、`static/`、`site-root/`、`vendor/`、`site.config.json`，拼出 `dist/`；GitHub Pages 与 haelcy.cn 两处发布端共用这一份源码。

## 一、目录职责

| 路径 | 职责 | 谁在用 |
| --- | --- | --- |
| `content/posts/*.md` | 文章与 memo（frontmatter 决定标题/日期/类型/分类/标签） | 构建读 |
| `content/pages/about.md` | 关于页正文 | 构建读 |
| `content/chronicle.json` | 关于页的「编年史」时间线数据 | 构建读 |
| `static/assets/` | 主题资源：CSS、JS、字体、图片，整目录拷进 `dist/assets/` | 构建拷、浏览器加载 |
| `site-root/` | 站点根文件：favicon、logo、`site.webmanifest`、`sw.js`、`portal.css`、`marked.esm.js`、好友圈 JSON | 构建拷到 `dist/` 根 |
| `scripts/build.mjs` | 唯一的构建脚本（Markdown → HTML，含分页、搜索索引、sitemap） | 本地 + CI + 服务器 |
| `scripts/*.mjs`、`scripts/*.py` | 辅助工具：`media-prep`（转码/缩略图）、`gen-placeholders`（占位图）、好友圈采集两个 py | 手动跑 / 采集 workflow |
| `deploy/` | 服务器部署脚本、`check-assets.mjs`（构建产物资源完整性自检） | 手动 / CI |
| `docs/` | 说明文档（本文件、使用指南、问题记录） | 人看 |
| `vendor/marked.esm.js` | Markdown 渲染库，构建时被 `import`（免 npm install） | 构建读 |
| `site.config.json` | 站名、简介、社交链接、友链列表 | 构建读 |
| `dist/` | 构建产物（git 忽略，随时可重建） | 浏览器 / 部署 |
| `css_rules.yaml`、`fc_settings.yaml` | 样式约定、好友圈采集参数（构建不读，留档参考） | 人 / 外部采集器 |
| `.github/workflows/` | `deploy.yml`（构建发布）、`fcircle-data.yml`（每日采集好友圈） | GitHub Actions |

## 二、数据流

```
content/*.md ─┐
static/       ├─→ scripts/build.mjs ─→ dist/ ─┬─→ GitHub Pages（base=/Blog）
site-root/    │                               └─→ 服务器每 5 分钟拉源码自建（base=/）
site.config.json ┘
```

发布：push 到 `main` → Actions 构建 → Pages 上线；同一 commit 再以 `SITE_BASE=__root__` 构建一次做自检。国内站不由 GitHub 推送，而是服务器 `haelcy-pull.timer` 主动拉取后本地构建。

## 三、红线：这几处改了会出问题

1. **图片目录名就是线上 URL**。`static/assets/img/<文章标题>/` 里 14 个目录（含空格、emoji、破折号）被文章正文直接引用为 `/assets/img/<标题>/<文件>`；改名 = 断图 + 旧链接失效。要改就得同时改正文和缓存。
2. **`portal.css` 与 `marked.esm.js` 各存两份，且内容不同**。
   - 页面里真正生效的是 `site-root/assets/` 那份（构建时拷到 `dist/assets/`，`build.mjs:1310` 优先读它）。
   - `static/assets/portal.css` 是旧路径的残留副本，改它等于没改。
   - `vendor/marked.esm.js` 只给**构建脚本**用；浏览器端 Portal 动态 `import('assets/marked.esm.js')`（`static/assets/js/portal-view.js:309`）加载的是 `site-root/assets/` 那份。两份是不同版本，别当成同一个文件。
3. **`content/posts/` 必须平铺**。构建直接 `readdirSync` 该目录，建子目录会导致文章被漏掉。
4. **`site.config.json`、`package.json`、`vercel.json` 必须留在仓库根**。前两个被脚本按相对路径读取，`vercel.json` 由 Vercel 平台读取，挪走即失效。
5. **路径里有空格和 emoji**。写 shell 命令时务必加引号，否则中文目录名会被拆断。

## 四、常用命令

| 目的 | 命令 |
| --- | --- |
| 构建 | `node scripts/build.mjs` |
| 本地预览 | `python -m http.server 8080 --directory dist` → http://127.0.0.1:8080/ |
| 检查产物引用是否全在 | `node deploy/check-assets.mjs` |
| Pages 版 + 根路径版双版本自检 | `bash deploy/verify-build.sh` |
| 图片转码 / 生成缩略图 | `node scripts/media-prep.mjs` |
