## 0. 先看懂这个项目（30 分钟，建立地图）

### 0.1 它到底是什么

一个**纯静态个人博客**：没有后端、没有数据库、没有 npm 依赖（`marked` 已经 vendor 进仓库）。
一份源码，发布到**四个入口**，页面内容完全一致，差别只在 URL 前缀和 canonical 域名。

以下为 **2026-10-13 本机实测**（广州、直连）：

| 入口 | 角色 | URL 前缀 | 谁在托管 | 实测结果 |
|---|---|---|---|---|
| `https://haelcy.cn/` | **主站**（`canonical` 指向它） | `/`（根路径） | **Vercel**（响应头 `Server: Vercel`，边缘 `X-Vercel-Id: sin1::…` = 新加坡） | `200`，0.35 s |
| `https://www.haelcy.cn/` | 主站别名，**只跳转不建站** | — | Vercel 边缘返回重定向 | `308` → `https://haelcy.cn/` |
| `https://haelcy-blog.vercel.app/` | Vercel 项目默认别名（回退入口） | `/` | Vercel | **直连不通**（`000`，国内被 SNI 阻断，与文档一致） |
| `https://anthony-hcy.github.io/Blog/` | GitHub Pages 镜像（保留） | `/Blog` | GitHub Pages | `200`，1.77 s |

两站的构建时间戳来自同一批构建（同一次 push）：

```bash
curl -s https://haelcy.cn/version.json                            # {"v":"2026-10-13T01:49:31.085Z"}
curl -s -x http://127.0.0.1:7897 https://anthony-hcy.github.io/Blog/version.json  # {"v":"2026-10-13T01:49:50.022Z"}
```

**全项目最核心的一句设计**：

> **一份源码、两次构建。** `site.config.json` 一个字不改，靠环境变量覆盖站点地址与子路径：
> `SITE_URL=https://haelcy.cn SITE_BASE=__root__ node scripts/build.mjs`
> （`__root__` 是约定值，代表「空前缀 / 根路径」；不用空串是因为「环境变量存在但为空」在不同 shell 下行为不一致。）

### 0.2 一次「发文章」到底发生了什么（完整链路）

```
你写 Markdown ——三个入口随便一个
  ├─ 电脑：content/posts/xxx.md  →  git push origin main
  ├─ 手机：/portal.html 用你自己的 GitHub PAT 调 GitHub REST API 提交
  └─ 机器人：每天 04:00（北京时间）Actions 采集友链数据并提交回仓库
        ↓  仓库 main 分支发生变化
   ┌────────────────────────┬─────────────────────────────┐
   │ GitHub Actions          │ Vercel（Git 集成）           │
   │ .github/workflows/      │ 监听到同一个 push            │
   │ deploy.yml              │ 跑同一条构建命令             │
   │ ① node scripts/build.mjs│ SITE_URL=https://haelcy.cn   │
   │   → dist/（/Blog 前缀） │ SITE_BASE=__root__           │
   │ ② upload-pages-artifact │ node scripts/build.mjs       │
   │   + deploy-pages        │ → dist/（根路径）            │
   │ ③ 再构建一次根路径版     │ → 边缘网络上线（约 1–3 分钟）│
   │   + check-assets.mjs 自检│                             │
   └────────────────────────┴─────────────────────────────┘
        ↓
  https://anthony-hcy.github.io/Blog/ 和 https://haelcy.cn/ 同时看到新文章
```

**两个容易踩的点（项目里真实发生过）**：
1. 机器人用 `GITHUB_TOKEN` 提交**不会触发 `push` 事件**，所以 `deploy.yml` 里加了
   `workflow_run: workflows: ["Update Friend Circle Data"]` 兜底（证据：`.github/workflows/deploy.yml:8-10`）。
2. Vercel **不做 clean URL**：手输 `/portal` 或 `/portal/` 会 404。所以仓库里加了
   `vercel.json:3-6` 把两者永久重定向到 `/portal.html`（实测 `/portal` → `308`）。

## 模块 1 · HTML / CSS / JavaScript（前端基础）

> 一句话：**这个博客没有后端、没有框架，页面上的一切都是原生三件套 + ES Module 写出来的。**
> 所以模块 1 不是"基础热身"，它是你日后改主题、改交互时唯一要动的层。

### 1.1 要学到什么程度（逐条自测）

- [ ] 能读懂语义化标签：`<article>` `<figure>` `<picture>` `<source>` `<video>` `<nav>`，知道 `srcset` / `sizes` / `loading="lazy"` 各管什么。
- [ ] CSS 会写：**自定义属性（变量）**、`@media` 断点、Flex、Grid、`aspect-ratio`、`object-fit`，以及 `prefers-color-scheme` / `prefers-reduced-motion` 这两个媒体查询。
- [ ] 讲得清**字体回退链**和 `unicode-range` 是干什么的（本项目用它让 emoji 不抢正文）。
- [ ] JS 会用：**ES Module**（`import` / `export`）、`async/await`、`fetch`、`IntersectionObserver`、事件委托、`localStorage`、模板字符串。
- [ ] 能解释三个"本项目特有"的问题：
  1. `<script type="module">` 和普通 `<script>` 到底差在哪？（提示：作用域、严格模式、默认 defer、可以 `import`）
  2. 为什么 `import` 的路径后面能跟 `?v=abc123`？（提示：查询串不影响模块解析，但能让浏览器换缓存键）
  3. 为什么脚本要放在 `<body>` 末尾、还带 `defer`？

**过关标准**：随便挑一个线上页面，用 DevTools 的 Elements 面板能说出每一层 `div` 是干什么的；改一个颜色、改一个间距、加一段交互，不用查资料。

### 3.4 模块 3 的三道必答题

1. **为什么用同步 `readFileSync` 而不是 `await readFile`？**
   构建脚本是一次性进程，没有任何并发收益，同步代码更好读、报错栈更直白。（对照：`check-assets.mjs` 也一样。）
2. **为什么不直接把 `<script>` 里的 `import` 路径写成带哈希？**
   因为源文件 `static/assets/js/*.js` 是给人读的；哈希只在 `dist` 里补，源文件保持干净（`:1348-1362`）。
3. **`dist/` 是"产物"，为什么仓库里还有一份？**
   本地 `dist/` 是上次构建留下的，方便 `npm run serve` 预览；它**不参与线上发布**（线上由 Actions/Vercel 各自重新构建）。`node_modules/marked` 同理是历史遗留——`build.mjs:12` 实际读的是 `vendor/marked.esm.js`，两者没有依赖关系。

## 模块 4 · Git 与 GitHub（版本管理的地基）

> 一句话：**这个项目的所有"自动"都建立在"一次 `git push`"上**。没有 Git，Actions 不跑、Vercel 不构建、Pages 不更新。

### 4.1 要学到什么程度（逐条自测）

- [ ] 会 `clone` / `status` / `add` / `commit` / `push` / `pull` / `log --oneline` / `diff` / `show`。
- [ ] 懂**暂存区**这个概念：为什么 `add` 和 `commit` 是两步，`git diff` 与 `git diff --staged` 差在哪。
- [ ] 会回退，并知道**哪种回退安全**：
  - `git revert <commit>` —— 新增一次"反向提交"，历史保留，**可以安全用在已推送的分支上**。
  - `git reset --hard <commit>` —— 直接抹掉本地历史，**已推送时会给别人造成灾难**。
  - `git restore <file>` —— 只丢弃某个文件的本地修改。
- [ ] 懂 `.gitignore`：写进去的**从未被跟踪过**的文件才会被忽略；**已经被跟踪的文件加 ignore 无效**，要先 `git rm -r --cached <路径>`。
- [ ] 会写规范的提交信息，知道 `feat/fix/docs/chore` 这类前缀的价值（本项目在用）。
- [ ] GitHub 侧会：建仓库、看 Actions/Pages 设置、生成**最小权限 PAT**、配 SSH key、看 `Insights → Network` 理解历史。
- [ ] 会排查"本地和远端不一致"：`git fetch` → `git status -sb` → 再决定 `pull --rebase` 还是 `merge`。

**过关标准**：能干净地完成"改一篇文章 → 提交 → 推送 → 在 GitHub 上看到 commit → 确认 Actions 被触发"；并且能把自己刚推错的一次提交安全回退。

### 4.3 五条必须刻进习惯的规矩

1. **`dist/`、`node_modules/` 永不入库**（本项目已如此）。生成物入库的下场是：每次构建都产生几百个文件的 diff，`git diff` 彻底失去意义。
2. **一次提交只做一件事**。本项目历史里能读到 `fix(portal): …`、`docs: …`、`chore(vercel): …` 这种干净的单点提交，所以 `git log` 才是一份可读的变更史。
3. **动 `.github/workflows/` 或 `scripts/build.mjs` 之前先开分支**，验证通过再合回 `main`——因为一推 `main` 就同时触发 Pages 构建和 Vercel 构建（两次上线）。
4. **PAT 绝不要提交进仓库**（Portal 把 PAT 存在浏览器 `localStorage`，见模块 9/16）；`.gitignore` 里再加一行 `*.env` / `keys/` 是廉价的保险。
5. **回退优先用 `revert`，不用 `reset --hard`**。你只有一条 `main`，"改写历史"没有任何收益，只有风险。

## 模块 5 · GitHub Actions（CI/CD 自动化）

> 一句话：**你 push 一次，GitHub 免费给你一台 Ubuntu 机器，跑你的脚本、发你的网站。**
> 这个项目有两个 workflow：`deploy.yml`（发布镜像站）和 `fcircle-data.yml`（每天采集友链数据）。

### 5.1 要学到什么程度（逐条自测）

- [ ] 会读/写 workflow 文件骨架：`name` / `on` / `jobs` / `runs-on` / `steps` / `uses` / `run` / `with` / `env`。
- [ ] 认识事件：`push`、`pull_request`、`schedule`（cron）、`workflow_dispatch`（手动按钮）、`workflow_run`（**别的 workflow 跑完之后**）。
- [ ] 会用 `permissions:` 做**最小授权**（本项目只给 `contents: read` / `pages: write` / `id-token: write`）。
- [ ] 会用 `concurrency:` 防止两个部署打架（`cancel-in-progress: true`）。
- [ ] 会往 `$GITHUB_OUTPUT` 写值，并在后面的 step 用 `if:` 读它（本项目用它决定"要不要花 80MB 下 ffmpeg"）。
- [ ] 会用 `${{ secrets.X }}` 存敏感值，并知道**`GITHUB_TOKEN` 是自动注入的、不需要自己建**。
- [ ] 懂一个关键事实：**用 `GITHUB_TOKEN` 产生的 push 不会再触发 `push` 事件**（防递归），所以机器人提交必须靠 `workflow_run` 兜底。
- [ ] 会排错：看 run 日志、`Re-run failed jobs`、`act` 本地跑（可选）。

**过关标准**：能读懂 `deploy.yml` 每一行；能自己加一个 step（比如构建后打印 `dist` 体积）；能解释"为什么机器人提交后镜像站也会更新"。

### 6.4 一个必答的判断题

> **为什么不能把 `https://haelcy.cn` 直接绑到 GitHub Pages 上，然后两边共用一个产物？**

## 模块 7 · Vercel 与海外托管（免备案主站）

> 一句话：**主站 `haelcy.cn` 现在的真实形态是"Vercel 海外托管"** —— 源站在海外，所以**不需要 ICP 备案**，也不要服务器、不要 nginx、不要 certbot。

### 7.1 先纠正一个最容易被旧资料带偏的事实

本工作区的旧版清单 `学习清单-从零掌握本项目.md`（2026-10-11）把主线写成"阿里云轻量服务器 + ICP 备案 + nginx + SSH"。**那是已经不存在的形态。** 现在的真实状态（`使用指南.md:192-196` 明确记载）：

- 已从「阿里云轻量服务器 + ICP 备案」改为 **Vercel 海外托管（免备案）**。
- 阿里云服务器**已退款**；`deploy/` 下的 nginx 配置与服务器脚本**全部废弃**（文件还留在仓库里，没删）。
- Cloudflare Pages 项目与 `pre/pre2` 测试域**也已删除**（Cloudflare 完全弃用）。
- 域名仍在**阿里云注册**，但**解析托管在阿里云云解析 DNS**（实测 NS = `dns13.hichina.com` / `dns14.hichina.com`）。

**所以"服务器"这一环现在整个消失了**：静态文件由 Vercel 的边缘网络提供，证书由 Vercel 自动签发与续期。

### 7.2 要学到什么程度（逐条自测）

- [ ] 知道 Vercel 的定位：**"连上 Git 仓库就自动构建 + 全球 CDN + 自动 HTTPS"**，免费 Hobby 档对个人静态站完全够用。
- [ ] 懂 Vercel 与 GitHub Actions 的**分工**：Actions 负责 **GitHub Pages 镜像站**；Vercel 负责 **主站**，它自己监听同一个仓库的 push（`使用指南.md:273`："主站不经过 GitHub Actions"）。
- [ ] 会配一个 Vercel 项目：**Root Directory / Framework Preset / Install Command / Build Command / Output Directory / Environment Variables** 六项一个不能错。
- [ ] 会绑域名、知道"绑域名不等于改 NS"（本项目 NS 一直没动，只在阿里云云解析加记录）。
- [ ] 懂 `vercel.json` 的作用：**项目级配置**（本仓库用它补 clean URL 重定向）。

## 模块 8 · 域名与 DNS（`haelcy.cn` 是怎么指向站点的）

> 一句话：**域名是"门牌号"，DNS 是"把门牌号翻译成地址的电话簿"。** 本项目换了三次托管（服务器 → Cloudflare Pages → Vercel），**域名一直没换，变的只是 DNS 里那几条记录。**

### 8.1 要学到什么程度（逐条自测）

- [ ] 讲得出一次访问的完整链路：浏览器 → 系统 DNS 缓存 → 递归解析器 → 根 → `.cn` 顶级域 → 权威 NS → 拿到记录 → 发起 HTTPS。
- [ ] 认识常用记录类型并知道各自用途：
  - `A` → 直接给 IPv4 地址；`AAAA` → IPv6；`CNAME` → 指向另一个域名；`TXT` → 验证/说明；`MX` → 邮件。
  - 本项目主站用的是 `A` / `CNAME`（由 Vercel 指定），没有 `MX`（不用域名邮箱）。
- [ ] **分清"注册商"与"解析托管商"**（最容易混的一对）：
  - 注册商 = 你从谁那儿**买**的域名（本项目：阿里云）。
  - 解析托管商 = 谁在**回答** DNS 查询，由 **NS 记录**决定（本项目：阿里云云解析，NS = `dns13.hichina.com` / `dns14.hichina.com`）。
  - **两者可以不是一家，本项目恰好是同一家。**
- [ ] 懂 `TTL` 是什么，以及"改记录后有缓存，不会立刻全球生效"。
- [ ] 会用命令行自己查：`nslookup` / `dig` / `Resolve-DnsName`，会用 RDAP 查域名到期时间。
- [ ] 懂两件与钱和合规有关的事：**域名实名认证**与**到期续费**（本项目域名注册在阿里云，到期日 2027-10-08）。
- [ ] 懂"**DNS 托管**"和"**CDN/代理**"是两件事 —— 本项目就踩过这个坑（见 8.3）。

**过关标准**：能用自己的话解释"为什么 Vercel 不用改 NS"，并能亲手在解析控制台加一条记录、等生效、验证。

### 8.3 三个必须记住的坑（本项目都真踩过）

1. **"解析托管在哪"≠"流量走哪"**。
   `使用指南.md:313-315` 记载：当时觉得站点慢，一度归因于"DNS 托管在 Cloudflare"，**真正原因是 Cloudflare 的橙云代理（proxy）把流量绕到了洛杉矶**。橙云开着的时候，DNS 回答的是 Cloudflare 的 IP，你的真实源站被藏起来了 —— 所以"慢"是代理的锅，不是解析的锅。
2. **备案 ≠ DNS**。
   国内服务器要备案，是因为服务器在境内；换成海外托管（Vercel）后**不需要备案**，域名和 DNS 完全不用动。旧清单把"备案"写成必经环节，是过时结论。
3. **绑域名 ≠ 改 NS**。
   Vercel 的推荐做法是在你现有的解析商（阿里云云解析）里**加记录**，NS 保持不变。只有你想把解析整体交给别人时，才改 NS —— 改 NS 会连带影响该域名下**所有**记录（包括邮件），风险更大。

## 模块 9 · GitHub REST API 与 Portal（"没有后端"的后台）

> 一句话：**这个博客的后台（Portal）没有任何服务器** —— 你的浏览器拿着一个 PAT（个人访问令牌）**直接调 GitHub 的 REST API**，把文章提交进仓库，再触发 Actions 重新构建。
> 模块 9 是全项目**技术含量最高、也最危险**的一章：PAT 就在浏览器里。

### 9.1 先建立正确的心智模型

```
你的浏览器（portal-view.js）
   │  ① 读：GET  /repos/{repo}/contents/{path}          ← 列目录、取文件、拿 sha 用于删除
   │  ② 写：Git Data API 六步（见下）                    ← 一次提交多个文件（正文 + 封面 + 视频）
   │  ③ 触发：POST /actions/workflows/deploy.yml/dispatches
   │  ④ 轮询：GET  /actions/workflows/deploy.yml/runs?per_page=3
   ▼
api.github.com   （Authorization: Bearer <PAT>，X-GitHub-Api-Version: 2022-11-28）
   ▼
GitHub 仓库 main 分支 → Actions 构建 → Pages 镜像站；同时 Vercel 也自动构建主站
```

**没有你自己的服务器，没有数据库，没有云函数。** 所有"后端"能力都是 GitHub 的 API。

### 9.2 要学到什么程度（逐条自测）

- [ ] 懂 REST 基础：URL 结构、方法语义（GET 读 / POST 建 / PATCH 改 / PUT 覆盖 / DELETE 删）、请求头、响应状态码（200 / 201 / 204 / 401 / 403 / 404 / 409 / 422 / 429）。
- [ ] 懂**鉴权**：`Authorization: Bearer <PAT>`；知道 PAT 的**细粒度权限**怎么选（本项目要 Contents: Read/Write、Actions: Read/Write）。
- [ ] 懂**限流**：未认证 60 次/小时；认证后 5000 次/小时；命中后是 **403/429** 且响应头带 `X-RateLimit-*`。
- [ ] 懂**API 版本头** `X-GitHub-Api-Version: 2022-11-28` 是干什么的（固定行为，避免上游悄悄改语义）。
- [ ] 懂 **CORS**：为什么浏览器能直接调 `api.github.com`（GitHub 明确允许），以及为什么不能直接调你自己的对象存储。
- [ ] 懂 **Git Data API 的四个对象**：`blob`（文件内容）→ `tree`（目录快照）→ `commit`（一次提交）→ `ref`（分支指针）。**这是"一次提交多个文件"的唯一正路**（`PUT /contents` 一次只能一个文件）。
- [ ] 懂**读文件的两套编码**：文本 `encoding: utf-8`、二进制 `encoding: base64`（图片）。
- [ ] 懂**前端不是安全边界**：`localStorage` 里的 PAT 一旦被 XSS 拿到，等于把仓库交出去。

**过关标准**：能用 curl / Apifox 手动完成"列目录 → 取文件 → 一次提交两个文件 → 触发 workflow → 查状态"，并知道每一步的失败码是什么意思。

### 9.6 安全红线（务必逐条确认）

1. **PAT 只能存在你自己的浏览器**，不要贴进聊天、不要提交进仓库、不要写进任何 `.md`/日志。
2. **PAT 权限给到最小**：只需要 `Contents: Read and write` + `Actions: Read and write`。**绝不要给 `admin:*`。**
3. **PAT 要设过期时间**（90 天或 1 年），过期后重新生成 —— 长期不过期的 PAT 一旦泄露就是永久后门。
4. **发现泄露立刻去 GitHub 撤销令牌**（Settings → Developer settings → Personal access tokens），撤销比"删提交"有效得多。
5. 明白这条**结构性风险**：Portal 页面任何一处 XSS（比如 Markdown 预览没转义）都可能把 `localStorage` 里的 PAT 发到第三方。本项目在预览处有 `esc()` 兜底（`:1090` `preview.innerHTML = md ? md.parse(wikiImagesToMd(body.value)) : '<p>'+esc(body.value)+'</p>'`），**但"有兜底"不等于"没有风险"**。

## 模块 10 · PWA / Service Worker / HTTP 缓存

> 一句话：**Service Worker 是你写的一个"站在浏览器和网络之间的小代理"** —— 它决定每次请求是走缓存还是走网络。
> 本项目对它的依赖很重：**缓存策略选错 = 部署了但用户看到的还是旧页面**（这个事故真发生过）。

### 10.1 要学到什么程度（逐条自测）

- [ ] 懂 SW 生命周期四阶段：**注册 → install → activate → 接管 fetch**，以及 `self.skipWaiting()` + `self.clients.claim()` 为什么必须写（不写用户要开两次才更新）。
- [ ] 会写三种最常用的缓存策略，并**讲清各自适用场景**：
  - `networkFirst` —— 内容型页面（导航请求）。**永远先要新的，网络失败才用缓存。**
  - `cacheFirst` —— 静态资源（图片、字体、图标）。URL 带了内容哈希就不会有"更新"问题。
  - `staleWhileRevalidate` —— 先回缓存同时后台更新。**用错地方就是"看到旧内容"的元凶。**
- [ ] 懂 **Cache Storage API**：`caches.open()` / `cache.put()` / `caches.keys()` / `caches.delete()`。
- [ ] 懂 **Range 请求与 206 响应**：视频/大文件的分段请求，以及**为什么"缓存了一个 206 分段"会导致视频只出第一帧**。
- [ ] 懂 **HTTP 缓存**：`Cache-Control: immutable`、`max-age`、`ETag`、以及"URL 里带内容哈希"为什么能让你放心上一年强缓存。
- [ ] 懂 **PWA 可安装性**：`manifest.webmanifest`（`name` / `start_url` / `scope` / `display` / `icons`）+ HTTPS + 一个能响应 `fetch` 的 SW。
- [ ] 懂"**SW 注册时机**"为什么会成为性能问题。

**过关标准**：能在 DevTools 的 Application 面板里说清当前缓存里有几个 Cache、分别装了什么；能解释"为什么部署了但页面没变"。

## 模块 11 · 媒体处理（图片 / 视频 / 实况照片 / ffmpeg）

> 一句话：**这个博客最"硬核"的一环不是前端也不是部署，是照片。**
> 手机直出的照片里可能**内嵌了一段视频**（安卓的"实况照片"/动态照片），而这个项目要靠**前端嗅探字节**把它拆出来、再靠 **ffmpeg 在 CI 里转码**成所有浏览器都能放的 H.264。

### 11.1 要学到什么程度（逐条自测）

- [ ] 认识常见图片格式并能说出取舍：**JPEG**（有损、通用）、**PNG**（无损、带透明）、**WebP**（更小、兼容性已够）、**AVIF**（更小、更慢）、**GIF**（动图、体积大）。
- [ ] 懂"有损压缩质量"这个参数（`-q:v 7` 这种）大概对应什么画质/体积，知道**先压再传**能省多少流量。

- [ ] 懂 **`aspect-ratio`** 的作用：在图片还没加载出来前就撑出正确高度，**避免页面跳动**（CLS）。
- [ ] 懂视频**容器与编码**的区别：`.mp4` 是容器，里面可能是 **H.264（兼容性最好）** 或 **HEVC/H.265（体积小但 Chrome/Firefox 桌面版放不了）**。

### 12.4 三道自测题

1. **同一篇文章在 `https://haelcy.cn/archives/x/` 和 `https://anthony-hcy.github.io/Blog/archives/x/` 都能打开，搜索引擎会认为是重复内容吗？本项目怎么处理的？**
   答：会。靠 `canonical` 指向主站（`SITE_URL` 决定），把镜像站页面的规范网址指到主站 —— 只是"声明"，镜像站本身并不禁止抓取。
2. **`robots.txt` 里 `Disallow: /` 是不是就等于"内容没被收录"？**
   不是。`robots.txt` 只禁止**抓取**，不禁止**收录**（别人可以从外链知道这个网址）。真想不收录得用 `<meta name="robots" content="noindex">`。
3. **为什么 `og:image` 用固定的 `logo.png` 而不是文章封面？**
   因为这是"最省事的正确"：分享卡片永远有图，不会因为某篇文章封面缺失或尺寸不合而显示空白。想更精致就给每篇文章单独生成 og 图 —— 那是另一个工作量。

## 模块 13 · 友链朋友圈采集（机器人每天替你跑一次）

> 一句话：**这不是"前端功能"，是一条独立的 CI 流水线**：一个 Go 写的采集器去读所有友链博客的 RSS/HTML，把结果写进 JSON 提交回仓库，前端只负责把 JSON 画出来。

### 13.1 要学到什么程度（逐条自测）

- [ ] 懂 **RSS 与 Atom**：都是 XML 订阅格式，Atom 更规范（**带命名空间**，解析时要处理 `xmlns`）；知道 `channel/item`（RSS）与 `feed/entry`（Atom）的对应关系。
- [ ] 会用 **Python 标准库**解析 XML（`xml.etree.ElementTree`）与发请求（`urllib.request`），**因为 CI 环境只有标准库，不能随便引第三方包**。
- [ ] 懂**反爬的现实**：伪装 `User-Agent`、设置超时、失败重试 + 退避；知道有些站点用 **TLS 指纹**判断"不是浏览器"，连 `curl` 都会被拒。
- [ ] 懂**定时任务 + 自动提交**这条链路的幂等性与"谁会触发谁"（机器人提交不触发 push → 需要 `workflow_run` 兜底，见模块 5）。
- [ ] 懂**数据契约**：前后端之间靠一个固定结构的 JSON 沟通，前端只认字段名。**字段名一改，前端整页空白。**
- [ ] 会处理**编码与终端转义**：CI 里子进程输出带 ANSI 颜色码会让 `json.loads` 失败（本项目真踩过）。
- [ ] 懂**子路径陷阱**：`pathBase()` 拼错就整页 404（本项目真踩过）。

**过关标准**：能自己加一个友链、手动触发一次 workflow、看到数据更新、并在页面上验证；能解释 `fcircle-data.json` 里每个字段从哪来。

## 模块 15 · 脚本能力（Bash / Python / Windows 差异）与构建自检

> 一句话：**这个项目里所有"自动化"都是脚本** —— Bash 在 CI 里跑，Python 做后处理，Node.js 做构建，Windows 侧还要处理 Git-Bash 特有的坑。
> 模块 15 不教你"写脚本的语法"，教你**写出能在 CI 里一次成功、并且出错时说得清原因的脚本**。

### 15.1 要学到什么程度（逐条自测）

- [ ] Bash：
  - [ ] 懂 `set -euo pipefail` 三个开关各管什么（遇错退出 / 用未定义变量报错 / 管道里任一环失败即失败），并知道**什么时候故意不用它**。
  - [ ] 会 `cd "$(dirname "$0")/.."` —— 让脚本不依赖"从哪调用"。
  - [ ] 会 `mktemp` 造临时文件并用 `rm -f` 清理。
  - [ ] 会**用数组传一组参数**（`SSH_OPTS=(-i "$KEY" -o …)` + `"${SSH_OPTS[@]}"`）。
  - [ ] 分清两种 heredoc：`<<EOF`（本地展开变量）与 `<<'EOF'`（**原样传给远端，不展开**）。
  - [ ] 会内联环境变量：`SITE_URL="$X" SITE_BASE=__root__ node scripts/build.mjs`。
  - [ ] 会做"**下载并校验**"（看退出码不够，要验内容）。
- [ ] Python：够用就好 —— 会用标准库读文件、发请求、解析 XML/JSON、写正则。**CI 里不要引第三方包。**
- [ ] Windows 侧：知道 Git-Bash（MSYS）**会改写形如 `/Blog` 的参数**变成 Windows 路径 —— 这就是为什么本项目的自检脚本**故意不接参数**。
- [ ] 会用**退出码 + stdout/stderr 分离**设计脚本，让它能被"当作函数"调用。

**过关标准**：能写一个"下载 → 校验 → 失败重试 → 成功才继续"的脚本；能解释 `check-assets.mjs` 为什么只往 stdout 打一个数字。

### 15.4 三个必答题

1. **为什么 `verify-build.sh` 只写 `set -u` 不写 `set -e`？**
   因为它要把全部断言跑完再汇总（`:18-38` 逐条检查），中途遇错退出就看不到完整结果。
2. **为什么 `check-assets.mjs` 把详细输出放 stderr？**
   见 `:78-84`：stdout 只留一个数字，才能被 `$(...)` 捕获当返回值用；细节给人看，不影响"把它当函数用"。
3. **为什么 CI 里的下载要"非空 + `xz -t` 校验"？**
   因为"HTTP 200"只代表拿到了响应，不代表拿到了正确内容（`deploy.yml:54-57` 记录的真实事故）。**凡是从第三方 CDN 拿东西，都要验内容。**

## 模块 16 · 安全与排错方法论（**最该最后学、最先用**）

> 一句话：**这个项目没有后端，所以它的安全风险全部集中在两个地方 —— 「浏览器里存的东西」和「从外部拿进来的东西」。**
> 而排错能力，比任何一项技术都更决定你能不能独立维护这个站。

### 16.1 安全：四条真实存在的风险面

#### 风险 1（最高危）· PAT 存在浏览器 `localStorage` 里

| 证据 | 说明 |
|---|---|
| `static/assets/js/portal-view.js:836-838`、`:889` | `state.token = readLS(LS.token)` / `writeLS(LS.token, token)` —— 令牌明文存在 `localStorage`。 |
| `static/assets/js/portal-view.js:896-901` | `signOut()` **只清 token / repo / email** 三个 key。 |
| `static/assets/js/post.js:4-9` | 文章页靠 `localStorage.getItem('portal_auth_token')` **决定是否显示"编辑"入口** —— 这只是显隐 UI，**不是权限校验**。 |
| `static/assets/js/portal-view.js:1090` | 预览渲染有 XSS 兜底：`preview.innerHTML = md ? md.parse(wikiImagesToMd(body.value)) : '<p>'+esc(body.value)+'</p>'` —— 注意"Markdown 渲染出来的 HTML"是**直接 innerHTML** 的，兜底只覆盖了"非 Markdown 分支"。 |

**结论**：Portal 页面里任何一处 XSS 都可能把 PAT 送出去。**PAT 权限要给最小（只需 Contents + Actions 的读写），必须设过期时间，泄露立刻撤销**（撤销比删提交有效）。

#### 风险 2 · 第三方脚本与第三方计数

- `问题记录.md:9-18`：不蒜子（访客统计）的 JSONP 被浏览器以 `ERR_BLOCKED_BY_ORB` 拦掉，导致 About 页 VIEWS 显示不出来。
- 项目的处理方式值得学：`static/assets/js/layout.js:446-458` 用 8 秒 watchdog 把占位符换成 `–`，**明确不显示误导性的 `0`**。**原则：第三方不可靠时要"降级显示未知"，而不是"显示错误的默认值"。**

#### 风险 3 · 外部依赖的来源

| 证据 | 说明 |
|---|---|
| `static/assets/js/shared/photoswipe.js:1-3` | 注释：PhotoSwipe 从 **CDN 改成本地 vendor**，原因是"jsdelivr 国内不稳且**跨域不被 SW 缓存（离线灯箱必挂）**"。 |
| `vendor/marked.esm.js` | marked 也是 vendor 进来的（`scripts/build.mjs:12`）；`.github/workflows/deploy.yml:29` 注释：**无 npm 依赖，无需 `setup-node` / `npm ci`**。 |
| `static/assets/ExSearch/ExSearch.js` + 同目录 jQuery（87KB） | 唯一的重依赖：`static/assets/js/layout.js:291-332` 把它做成**懒加载**（`:329-330` 先 jquery 再 ExSearch，`:332` 注入后 `input.focus()` 触发打开）。**"第三方库要本地化"和"重依赖要懒加载"是两条独立的决策。** |

#### 风险 4 · 内容安全（你写的东西会变成 HTML）

- `scripts/build.mjs:149`：Markdown 图片被渲染成 `<figure>` HTML —— **Markdown 里的原始 HTML 是被放行的**（marked 默认行为）。
- `scripts/build.mjs:81-82`、`:1455-1460`：双链/裸文件名解析不到时**构建失败退出**（不是静默放过）。**这是"宁可构建失败，不要上线坏页面"的取舍。**
- `scripts/build.mjs:614-657` 的头部 meta 清单里**没有 Content-Security-Policy**；要加 CSP 必须把 `api.github.com`、字体域名等纳入白名单，否则 Portal 直接报废。**这是"想加固时必须先想清楚代价"的典型。**

### 16.3 排错五步法（把这五步变成肌肉记忆）

1. **先确定"看到的现象"是不是真的** —— 换浏览器（无扩展）/ 换网络（关代理、开代理）/ 无痕窗口 / 直连 curl 对比。**本项目一半的"故障"是这类环境差异**（`*.vercel.app` 被阻断、不蒜子被 ORB 拦、CDN 返回错误页）。
2. **分清"哪一层"** —— 是 **产物错了**（`dist/` 里内容不对 → 构建问题）、**传输错了**（网络/缓存/SW → 命中旧版本）、还是**运行错了**（前端 JS 报错 → DevTools Console）。
3. **打开证据面板** —— DevTools 的 `Console` / `Network`（看 `(ServiceWorker)` 标记与状态码）/ `Application → Service Workers & Cache Storage`。**模块 10 的四个动作就是这里的标准流程。**
4. **查注释不如查"真值"** —— 注释会漂移（G 组两个实例）。真值优先级：**代码 > 配置文件 > 实际产物 > 注释 > 文档**。
5. **修完必须回验 + 记录** —— 本项目把每次故障写进 `问题记录.md`，把结论写进 `使用指南.md`。**没写下来的修复，半年后等于没修过。**
